정의

객체 탐지(Object Detection)는 이미지 안의 관심 객체마다 클래스(무엇)와 위치(Bounding Box, 어디)를 동시에 예측하는 기술입니다. 객체 인식(Recognition)을 확장한 과제로 볼 수 있습니다.

분류와의 결정적 차이는 객체의 개수가 정해져 있지 않다는 점입니다. 모델은 0개부터 수백 개까지, 이미지마다 다른 수의 객체를 찾아내야 합니다.

주요 활용 분야

  • 자율 주행: 차량·보행자·신호등·표지판 탐지
  • 보안·감시: 침입자, 이상 행동, 유기 물체 감지
  • 의료 영상: X-ray·내시경에서 병변 위치 표시
  • 제조·검사: 생산 라인의 결함·불량 위치 탐지
  • 리테일·물류: 진열 상품 인식, 재고·택배 계수
01 개념

탐지 모델의 입력과 출력

하나의 객체 = 클래스 + 박스 좌표 + 신뢰도 점수

중심 좌표 (x, y)와 너비·높이 (w, h)로 표현한 바운딩 박스
출력 예) { class: "person", conf: 0.94,
  box: (x=0.47, y=0.50, w=0.19, h=0.63) }

출력의 세 가지 구성 요소

  • 클래스 확률: 각 클래스일 확률 (Softmax 또는 Sigmoid)
  • 박스 좌표: 객체를 둘러싼 사각형의 위치와 크기 (4개 값)
  • 신뢰도 점수: 이 예측을 얼마나 믿을 수 있는지 (0~1)

박스 좌표 표현 방식

  • xywh: 중심점 + 너비·높이 (YOLO 형식, 0~1로 정규화)
  • xyxy: 좌상단 (x₁, y₁) + 우하단 (x₂, y₂) (PASCAL VOC 형식)
  • COCO: 좌상단 (x, y) + 너비·높이, 픽셀 단위

탐지가 어려운 이유

  • 같은 클래스라도 크기·종횡비·자세가 제각각
  • 객체끼리 가려지거나(occlusion) 밀집되어 있음
  • 후보 위치의 대부분이 배경 → 극심한 클래스 불균형
  • 실시간 서비스를 위한 속도와 정확도의 트레이드오프

Viola–Jones 2001

Haar-like 특징 + 적분 이미지 + AdaBoost 캐스케이드. 대부분의 윈도우를 초기 단계에서 빠르게 걸러내 실시간 얼굴 탐지를 처음 실현했습니다.

HOG + SVM 2005

픽셀 그래디언트 방향의 히스토그램(HOG)으로 윤곽을 표현하고 선형 SVM으로 분류. 보행자 탐지의 표준이 되었습니다.

DPM 2008

객체를 여러 부분(part)의 변형 가능한 조합으로 모델링. 딥러닝 이전 PASCAL VOC의 최고 성능 방식이었습니다.

구분전통적 방식딥러닝 방식
특징 추출사람이 설계 (HOG, Haar)CNN이 데이터에서 자동 학습

학습 방식특징·분류기를 단계별로 따로전체를 end-to-end로 학습
데이터적은 데이터로도 동작대규모 레이블 데이터 필요
연산 자원CPU로 충분GPU 필요 (경량 모델은 엣지 가능)

전환점

2012년 AlexNet이 ImageNet 분류에서 CNN의 위력을 보여준 뒤, 2014년 R-CNN이 CNN 특징을 탐지에 적용해 PASCAL VOC 성능을 크게 끌어올렸습니다. 이후 탐지 연구는 딥러닝 중심으로 전환됩니다.

02 구조와 작동 원리

앵커 박스와 바운딩 박스 회귀

박스를 처음부터 그리지 않고, 기준 박스를 조금씩 고친다

한 셀 중심에 여러 모양의 앵커를 두고, 정답과 가장 잘 맞는 앵커의 오프셋을 학습

앵커 박스란?

특징맵의 모든 위치에 미리 정해 둔 여러 크기·종횡비의 기준 박스입니다. 모델은 박스를 직접 그리는 대신, 앵커를 정답에 맞추려면 얼마나 옮기고 늘려야 하는지(오프셋)를 예측합니다.

예) Faster R-CNN: 3가지 크기 × 3가지 비율(1:2, 1:1, 2:1) = 위치당 9개

바운딩 박스 회귀: 무엇을 예측하는가

tx = (x − xa) / wa    ty = (y − ya) / ha
tw = log(w / wa)     th = log(h / ha)

(xa, ya, wa, ha)는 앵커, (x, y, w, h)는 정답 박스. 모델은 (tx, ty, tw, th)를 예측하고, 추론 시 역변환으로 최종 박스를 복원합니다. 앵커 크기로 나누고 log를 취하므로 크고 작은 객체를 같은 스케일로 안정적으로 학습합니다.

앵커-프리(Anchor-free) 방식

  • FCOS: 각 위치에서 박스 네 변까지의 거리 (l, t, r, b)를 직접 예측
  • CenterNet: 객체 중심점을 히트맵으로 찾고 크기를 회귀
  • 앵커 크기·비율 같은 하이퍼파라미터가 사라져 설계가 단순 (YOLOv8 이후 채택)
02 구조와 작동 원리

IoU: 박스가 얼마나 잘 맞았는가

학습의 정답 할당, 후처리, 평가까지 모두 IoU 하나로 판단

IoU = 면적(예측 ∩ 정답) / 면적(예측 ∪ 정답)
0이면 전혀 겹치지 않음, 1이면 완전히 일치
조금만 어긋나도 IoU는 빠르게 떨어진다 → 0.5도 생각보다 엄격한 기준

① 학습: 정답 할당(Label Assignment)

각 앵커(또는 위치)를 정답 박스와 비교해, 무엇을 학습시킬지 정합니다.

IoU ≥ 상한 → 양성(Positive): 클래스 + 박스 학습
IoU < 하한 → 음성(Negative): "배경"으로 학습
그 사이 → 무시(Ignore)

예) RPN은 0.7 / 0.3, RetinaNet은 0.5 / 0.4를 기준으로 사용

② 후처리와 ③ 평가

NMS: 서로 IoU가 높은 예측 박스는 같은 객체로 보고 중복 제거

평가: 정답과 IoU ≥ 임계값(보통 0.5)이고 클래스가 맞으면 정탐(TP), 아니면 오탐(FP)

IoU 계열 손실 함수

GIoU: 겹치지 않을 때도 두 박스를 가까이 끌어당기는 항 추가 · DIoU: 중심점 거리 반영 · CIoU: 종횡비까지 반영 (YOLOv4·v5 등에서 사용)

02 구조와 작동 원리

손실 함수: 모델은 무엇을 학습하는가

"무엇인가"를 맞히는 분류 손실 + "어디인가"를 맞히는 회귀 손실

Ltotal = Lcls + λ · Lbox ( + Lobj )

분류 손실은 모든 샘플(양성+음성)에, 박스 손실은 양성 샘플에만 적용합니다. 배경에는 맞출 박스가 없기 때문입니다. λ는 두 손실의 균형을 맞추는 가중치입니다.

분류 손실

Classification Loss
기본: Cross-Entropy

예측한 클래스 확률과 정답의 차이를 측정

문제: 배경이 압도적으로 많음

이미지당 수만 개 후보 중 객체는 몇 개뿐. 쉬운 배경 샘플의 작은 손실이 쌓여 학습을 지배합니다.

해결: Focal Loss (RetinaNet)
FL(pₜ) = −αₜ (1 − pₜ)^γ · log(pₜ)

이미 잘 맞히는(pₜ가 큰) 샘플의 가중치를 줄여 어려운 샘플에 집중. 보통 γ = 2, α = 0.25

박스 회귀 손실

Localization Loss
Smooth L1 (Fast/Faster R-CNN)
0.5·x²  (|x| < 1)
|x| − 0.5  (그 외)

오프셋 (tx, ty, tw, th) 오차에 적용. 오차가 클 때 L2보다 완만해 이상치에 덜 민감합니다.

IoU 계열 (최신 모델)
L = 1 − IoU + (페널티 항)

좌표를 따로 보지 않고 박스 전체의 겹침을 직접 최적화 → 평가 지표와 학습 목표가 일치

객체성·품질 점수

Objectness / Quality
Objectness (YOLO 계열)

이 박스 안에 객체가 있을 확률을 BCE로 학습

최종 점수 = objectness × 클래스 확률
Centerness (FCOS)

객체 중심에서 먼 위치의 저품질 박스 점수를 낮춤

왜 필요한가?

분류 점수만으로는 박스 위치의 정확도를 알 수 없어, NMS에서 더 정확한 박스를 남기도록 돕습니다.

2-Stage 탐지기: R-CNN 계열의 작동 원리

① 객체가 있을 만한 곳을 찾고 → ② 그 영역을 정밀하게 분류·보정

R-CNN 2014

  1. Selective Search로 후보 영역 약 2,000개 생성
  2. 각 영역을 고정 크기(227×227)로 변형
  3. 영역마다 CNN을 따로 통과시켜 특징 추출
  4. SVM으로 분류 + 박스 회귀로 위치 보정
한계: 영역마다 CNN 반복 → 이미지당 수십 초

Fast R-CNN 2015

  1. 이미지 전체를 CNN에 한 번만 통과
  2. 후보 영역을 특징맵 위에 투영
  3. RoI Pooling으로 고정 크기(7×7) 특징 추출
  4. 분류 + 박스 회귀를 하나의 손실로 동시 학습
개선: 특징 공유로 대폭 가속 / 병목: 후보 생성(CPU)

Faster R-CNN 2015

  1. 백본 특징맵을 모든 단계가 공유
  2. RPN: 각 위치의 앵커 9개마다 객체 여부 + 오프셋 예측
  3. 상위 후보(약 300개)만 RoI Pooling
  4. 최종 분류 + 박스 정제
후보 생성까지 신경망으로 → end-to-end, 약 5 FPS

03 대표 모델

1-Stage 탐지기: YOLO · SSD · RetinaNet

후보 영역 단계 없이, 한 번의 forward pass로 클래스와 박스를 동시에

7 × 7 격자 · 중심이 속한
셀(주황)이 탐지 담당

YOLO의 작동 원리

  1. 이미지를 S × S 격자로 분할
  2. 객체 중심이 들어간 셀이 그 객체를 담당
  3. 각 셀이 B개 박스 (x, y, w, h, conf) + C개 클래스 확률을 예측
  4. 신뢰도 임계값과 NMS로 최종 박스 선택
출력 텐서 = S × S × (B·5 + C)
YOLOv1: 7 × 7 × (2·5 + 20) = 7 × 7 × 30

YOLO 계열의 발전

  • v1 (2016): 탐지를 하나의 회귀 문제로 → 실시간 탐지의 시작
  • v2·v3: 앵커 도입, 3개 스케일에서 예측 (작은 객체 대응)
  • v4·v5: CSP 백본, PAN, Mosaic 증강 → 속도·정확도 동시 향상
  • v8 이후: 앵커-프리, 분리형 헤드, 다양한 크기의 모델 제공

SSD Single Shot MultiBox Detector, 2016

해상도가 다른 여러 특징맵 각각에서 default box(앵커)를 예측. 고해상도 맵은 작은 객체, 저해상도 맵은 큰 객체를 담당해 한 번에 다양한 크기에 대응합니다.

RetinaNet 2017

1-Stage가 2-Stage보다 부정확했던 핵심 원인을 전경·배경의 극심한 불균형으로 규명. Focal Loss + FPN으로 1-Stage 속도에 2-Stage 수준의 정확도를 달성했습니다.

03 대표 모델

후처리 NMS, 그리고 NMS가 필요 없는 DETR

중복 박스를 규칙으로 지울 것인가, 처음부터 하나만 예측하게 학습할 것인가

NMS (Non-Maximum Suppression)

중복 예측 박스 제거
처리 단계
  1. 신뢰도 점수 순으로 박스 정렬
  2. 가장 높은 박스를 결과로 확정
  3. 확정 박스와 IoU ≥ 임계값(예: 0.5)인 박스 제거
  4. 남은 박스가 없을 때까지 ②~③ 반복 (클래스별)
한계와 개선

실제로 겹쳐 있는 객체(군중, 주차된 차량)까지 지울 수 있음 → Soft-NMS는 제거 대신 IoU에 비례해 점수를 낮춰 밀집 객체 탐지를 개선합니다.

DETR (DEtection TRansformer, 2020)

탐지를 "집합 예측" 문제로
CNN백본
→
Transformer인코더
→
디코더+ Object Query N개
→
N개 예측{클래스, 박스}
헝가리안 매칭 (Hungarian Matching)

N개(예: 100개)의 예측과 정답 객체를 1:1로 최적 매칭해 손실을 계산합니다. 매칭되지 않은 예측은 "객체 없음(∅)"으로 학습되므로, 같은 객체에 여러 박스를 내면 페널티를 받습니다.

의미

중복이 학습 단계에서 억제되어 NMS와 앵커가 필요 없는 단순한 end-to-end 구조. 어텐션으로 이미지 전체 문맥을 활용합니다.

한계와 후속 모델

학습 수렴이 매우 느리고(수백 epoch) 작은 객체에 약함 → Deformable DETR(국소 어텐션), DINO(수렴 가속), RT-DETR(실시간)로 개선되었습니다.

04 성능 평가

탐지 성능 평가: Precision · Recall · mAP

"얼마나 정확하게"와 "얼마나 빠짐없이"를 함께 본다

판정 기준 IoU 임계값 + 클래스 일치

  • TP (정탐): 정답과 IoU ≥ 임계값, 클래스 일치
  • FP (오탐): 없는 객체를 찾았거나, 위치·클래스가 틀림, 중복 예측
  • FN (미탐): 찾아내지 못한 정답 객체
Precision = TP / (TP + FP)  → 예측 중 맞은 비율
Recall    = TP / (TP + FN)  → 정답 중 찾은 비율
신뢰도 임계값을 낮출수록 Recall은 오르고 Precision은 떨어집니다. 이 곡선 아래 면적이 AP입니다.

AP와 mAP 계산

  1. 한 클래스의 모든 예측을 신뢰도 순으로 정렬
  2. 위에서부터 TP/FP를 판정하며 누적 Precision·Recall 계산
  3. PR 곡선 아래 면적 = 그 클래스의 AP
  4. 모든 클래스의 AP 평균 = mAP

벤치마크별 기준

  • PASCAL VOC: mAP@0.5 (IoU 0.5 한 가지 기준)
  • MS COCO: AP@[0.5:0.95], IoU 0.5~0.95를 0.05 간격 10단계로 평균 → 위치 정확도까지 엄격히 평가
  • 세부 지표: AP50, AP75, 크기별 APS · APM · APL

속도와 효율

  • FPS / 지연 시간(ms): 초당 처리 이미지 수, 1장 처리 시간
  • 파라미터 수 · FLOPs: 모델 크기와 연산량
  • 실제 비교는 같은 하드웨어에서 정확도–속도 곡선으로

정리

객체 탐지 = 무엇이 어디에 있는지를 한 번에 예측

개념

  • 여러 객체의 클래스 + 바운딩 박스를 동시에 예측
  • 출력: 클래스 확률 · 박스 좌표(4개 값) · 신뢰도
  • 수작업 특징(HOG, Haar) → CNN 자동 학습으로 전환

작동 원리

  • Backbone(특징) → Neck(FPN 융합) → Head(예측)
  • 앵커 기준 오프셋 회귀, 최근엔 앵커-프리로 단순화
  • IoU로 정답 할당 · 분류 손실 + 박스 손실(Focal, CIoU)

대표 모델

  • 2-Stage: R-CNN → Fast R-CNN → Faster R-CNN(RPN)
  • 1-Stage: YOLO(격자), SSD(다중 스케일), RetinaNet(Focal Loss)
  • Transformer: DETR, 헝가리안 매칭으로 NMS 제거

평가

  • IoU 임계값으로 TP / FP / FN 판정
  • PR 곡선 면적 = AP, 클래스 평균 = mAP
  • COCO AP@[0.5:0.95] + FPS로 정확도와 속도 함께 비교
